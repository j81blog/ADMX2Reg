# ADMX2Reg 1.0.0

First public release of ADMX2Reg: a portable Group Policy editor that turns ADMX-based policy settings into `.reg` files, PowerShell scripts or `Registry.pol` files. You build GPOs the way you would in the Group Policy Management Console, but nothing is ever applied to the machine you work on.

## Highlights

- **Works like gpedit.** Category tree, policy list, and the familiar Not Configured / Enabled / Disabled dialog with all options generated from the ADMX files.
- **Three export formats.** `.reg`, PowerShell (a standalone, idempotent script or a minimal command list) and `Registry.pol` for LGPO.exe or a GPO in SYSVOL.
- **Live export preview.** See the exact `.reg`, PowerShell or `Registry.pol` output of the open GPO while you edit.
- **Import.** Load an existing `.reg` or `Registry.pol` and map its values back onto policies. Values that match no policy are kept, so an import never loses data.
- **Portable.** One exe, no installation, no .NET runtime needed. Settings and GPOs live next to the exe.

## Features

### Templates
- Reads any PolicyDefinitions folder: the local store (default), a domain central store (with detection), or your own folder.
- Ship your own templates: a `PolicyDefinitions` folder next to the exe is picked up automatically.
- ADML files are read from language subfolders or from next to the ADMX files. The language follows Windows, with a fallback to en-US, and can be changed in Settings.

### Editing
- Multiple GPOs, each with Computer and User Configuration, opened side by side in tabs.
- Search across policy names, help text, registry keys and value names.
- "Configured only" filter that also trims the tree to what is set in the GPO.
- Windows version filter that hides policies limited to other Windows versions, with a warning icon on configured settings that do not match.
- Duplicate GPOs and copy settings between GPOs.
- Changes are saved immediately, one JSON file per GPO.

### Export
- Follows the Group Policy engine: Enabled writes the policy value and its options; Disabled writes the disabled value or removes the value.
- `.reg` files are saved as UTF-16 like regedit.
- PowerShell scripts run on Windows PowerShell 5.1 and PowerShell 7, support `-WhatIf` and `-Verbose`, only change values that differ, and check for elevation when they touch HKLM.
- `Registry.pol` is written as `Machine\Registry.pol` and `User\Registry.pol`.
- GPMC-style HTML settings report.

### App
- Windows 11 Fluent design with light and dark theme.
- Collapsible navigation rail, resizable panels, and help icons that explain the less obvious options.
- Keyboard shortcuts: Ctrl+K or Ctrl+F (search), Ctrl+N (new GPO), Ctrl+W and Ctrl+Tab (tabs), F5 (reload), Enter (edit setting).

## Requirements

- 64-bit Windows 10 or 11, or Windows Server (x64)
- No installation and no .NET runtime required

## Known limitations

- The Windows version filter can tell Windows 10 from Windows 11, but not feature updates such as 23H2 and 24H2: the ADMX files give them all the same version. Deprecated policies still labeled "At least Windows ..." stay visible.
- A `.reg` file cannot clear only the values of a key. For list policies it deletes and recreates the key, which also removes its subkeys. The PowerShell and `Registry.pol` exports clear only the values.
- User Configuration settings in `.reg` and PowerShell exports apply to the user who runs them. Use `User\Registry.pol` to target other users.
- `Registry.pol` output is covered by round-trip tests over all policies in the Windows templates. If LGPO.exe or Group Policy reads a file differently than expected, please open an issue.
